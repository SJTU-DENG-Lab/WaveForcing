Abstract

Real-time long-video generation requires continuous output with consistent appearance and natural motion. Existing chunk-wise autoregressive methods face challenges in both generation efficiency and long-video quality: serialized denoising and history-cache refresh require two forward passes even with one-step denoising, and longer rollouts can degrade quality and cause camera drift. We propose Wave Forcing (WF), which co-designs generation, training, and execution for continuous video output with multi-step denoising. WF uses chunk-wise causal attention to access earlier, cleaner chunks before their denoising is complete, and distributes staggered denoising and cache-refresh stages across full-model replicas to achieve 1F1C: one output chunk per concurrent forward round after pipeline fill. To adapt the model to this continuous generation process, we develop a three-stage training procedure that successively introduces mixed-noise denoising, motion supervision, and causal adaptation using self-generated history. To execute this process efficiently, Wave Runtime (WaveRT) uses Wave Parallelism (WP) for early K/V delivery and communication–computation overlap, together with optimized kernels and pipelined VAE decoding.

Experiments on Wan2.1-T2V-1.3B show that 5-step WF maintains overall quality comparable to Rolling Forcing while achieving higher Dynamic Degree on both short and long videos. Our system efficiency experiments show that 4-step WF achieves 147.6 DiT FPS and 134.8 end-to-end FPS on eight H200 GPUs, yielding 7.07× the single-GPU end-to-end throughput. In DiT-only tests with matched SageAttention+W8A8 backends, denoising steps, and GPU counts, WP delivers up to 2.53× the throughput of the faster of the Ulysses and Ring context-parallel baselines across six model scales (1.3B–14B).

Method · Wave Forcing

A bounded-width causal wavefront.

Earlier chunks run later denoising stages while newer chunks run earlier ones. Each denoising stage and the store pass own a full-model replica, so the staggered tasks advance together as a moving wavefront.

Follow the diagonal: chunk i is at stage s in round k = i + s.
Sequential · NF1C

N forward rounds per chunk

Chunk-wise autoregressive methods such as Self Forcing and Causal Forcing denoise each chunk on top of earlier content, then run one more forward pass, the store, to refresh the K/V history from the clean result. Denoising and store sit between consecutive outputs, so even one-step denoising needs two forward passes per chunk.

Wave Forcing · 1F1C

One chunk per concurrent forward round

WF keeps every denoising update but staggers them: with S denoising stages plus store on S + 1 replicas, one completed chunk leaves the pipeline per round after fill. Chunk-wise causal attention keeps full attention within a chunk; across time, query slot s reads K/V slot j only if j ≥ s, which means itself and all cleaner predecessors, never a later chunk.

Method · Training

Training for the deployment graph.

The causal mask removes access to later, noisier chunks and changes the conditioning Rolling Forcing learned. Three stages adapt Wan2.1-T2V-1.3B to it.

Only WF is deployed, but Stage 3 trains on RF, WF and SF rollouts. Dropping any one of them hurts.
1

Mixed-noise initialization

RF's mixed-noise joint-denoising setup, with bidirectional attention across chunks at different noise levels. Each step samples an RF or an SF rollout with equal probability and trains with DMD. SF rollouts help stabilize motion.

DMDRF | SF rollout
2

Off-policy DMD

Following LPM 1.0: consecutive teacher chunks are re-noised at staggered timesteps, with earlier teacher chunks as clean K/V history. DMD and LPIPS supervise the same prediction, adding stronger motion and subject guidance.

DMD + LPIPSλₚ = 0.25
3

Causal adaptation, self-generated history

Each iteration uniformly samples a self-generated RF, WF or SF rollout for on-policy DMD. The WF branch uses the causal context, including store-refreshed history from its own outputs.

on-policy DMD⅓ RF + ⅓ WF + ⅓ SF

The 4-step student starts from SF's ODE initialization. The 5-step student reuses the released RF weights and skips Stage 1.

System · Wave Runtime

Wave Parallelism hides K/V delivery behind compute.

WF exposes stage concurrency, but K/V dependencies can still stall attention. WaveRT, built on SGLang Diffusion's model implementation, publishes K/V early from stage-owned replicas and overlaps delivery with computation when cleaner producers run ahead.

K/V ships right after QKV + RoPE, so it is usually ready before the consumer's attention needs it.

Stage-owned replicas

Each denoising stage and the store own a full-model GPU replica. Rank s updates chunk k − s and hands it to rank s + 1 for the next round.

Early publication

Cleaner ranks read fewer keys, so they can run ahead. K/V is published after QKV + RoPE, and readiness is checked just before attention.

we = max(0, τe − Δe)

Paged delivery

K/V is written directly into ordered attention slots and signalled ready before use, with no remote concatenation. Attention consumes the same K/V values as synchronized execution.

Kernels + pipelined VAE

SageAttention and W8A8 speed up local operators. The VAE decoder is split into profile-balanced contiguous stages on dedicated GPUs, overlapping DiT.

Removing WF gives the steadiest camera but halves motion (48.12). Removing SF degrades quality. The full recipe is the only one with no unusable score.

Limitations

What's still open.

With S denoising steps, WP runs S + 1 stages, so its width is set by the step count.

The VAE output path

Pipelining overlaps and partitions decoding but doesn't remove its finite capacity. The DiT/E2E gap (147.58 vs 134.81 FPS at 4 steps) is consistent with residual decoder and output-path limits; matched VAE-on/off runs are needed to isolate the bottleneck.

Training complexity

Simplifying mixed-noise initialization, teacher guidance and causal adaptation to self-generated history, while keeping motion and long-video stability, remains open.

Scalability

Pipeline width is bounded by the number of denoising steps, which limits how far one pipeline scales to more GPUs. WP's advantage over CP also narrows for larger models.
